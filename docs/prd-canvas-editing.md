# PRD — Direct manipulation of the schematic

Status: DRAFT for review. Nothing here is built; this document is the
proposal. Decisions that bound it are recorded in
[decisions/0009-canvas-structured-source-editing.md](decisions/0009-canvas-structured-source-editing.md).

## 1. Vision

The canvas becomes an editor, not just a viewer. A user who never opens
a `.zen` file can place components, wire them, name nets, and ship a
board — while every gesture lands as a small, reviewable text diff and
the agent remains a first-class collaborator on the same document. This
is the product's founding bet (docs/product.md): GUI-first AND
agent-first, with source as the implementation detail that makes both
trustworthy.

The bar is **agent-collaborative**, not "rival KiCad for solo
authoring": human and agent edit the same live board fluidly, sharing
one model. The human draws a wire; the agent sees it in the next build
and continues. The agent adds a part; the human drags it into place.
Either can drive. The interaction style is **full manual canvas** —
click-to-place, drag pin-to-pin to wire, double-click a label to
rename, rubber-band select — direct manipulation in the KiCad/Figma
sense, not form-guided.

## 2. Non-negotiable principles

1. **Source is truth; gestures are edits.** Every canvas action becomes
   a deterministic mutation of `.zen` / `etchable.toml` / part cards.
   No parallel model, no hidden state, nothing the rebuild can't
   reproduce. (The contract drag-to-move already honors.)
2. **The rebuild is the confirmation.** Gestures write files; the
   watcher rebuilds; the canvas shows the result. No optimistic canvas
   state that can drift from the build.
3. **Agent parity.** Every verb the GUI gets, the agent can invoke
   (MCP), and vice versa. One implementation per verb, two front doors.
4. **Honest refusal beats silent breakage.** Zener is a real language;
   instances can be produced by loops and computed expressions. Editing
   operations that can't be applied safely REFUSE with a reason ("this
   instance is generated by a loop — edit the source or ask the
   agent"), never guess.
5. **Concurrency-safe.** Every write is guarded by the build's
   `source_hash` (the existing save_positions token). A stale gesture
   is rejected and re-offered after the rebuild, never silently
   misapplied.

## 3. Vocabulary

- **Authored file** — a `.zen` file inside the project root the user or
  agent owns: the board entry, `components/*.zen`, local modules.
  Stdlib and vendored files are never edit targets.
- **Literal instance** — an instance whose creating call is a top-level
  statement in an authored file with a literal `name="..."` kwarg
  (e.g. `Resistor(name="R_LIMIT", ...)`). Editable.
- **Generated instance** — anything else: loops, comprehensions,
  computed names, calls inside functions, `**kwargs` splats.
  Structurally read-only from the canvas.
- **Literal net** — a net defined by a top-level literal assignment
  (`LED_A = Net("LED_A")`, `VCC = Power("VCC_3V3")`, io declarations).
  Renameable/rewireable.
- **Edit verb** — one semantic operation in `zen_build::edit`
  (add_instance, connect_pins, rename_net, …), exposed to the canvas as
  a Tauri command and to the agent as an MCP tool.

## 4. Architecture: the edit layer

### 4.1 `zen_build::edit` — writers

A new module beside `positions.rs` and `scaffold.rs`, following their
contracts:

- **Span surgery.** Writers parse the authored file with the starlark
  parser (already in zen-build's dependency set — the only crate
  allowed to touch it), locate the statement/expression span the verb
  targets, and replace or insert minimal byte ranges. No AST
  re-printing: untouched bytes are byte-identical after every edit, so
  hand-written comments and formatting survive and diffs read as the
  change.
- **One write per file per gesture.** A gesture that touches a file's
  program text AND its `# pcb:sch` block (e.g. place-component) folds
  both into a single write so the watcher fires once — the scaffold
  precedent (`.zen` last, complete unit).
- **Name-anchored application.** Writers locate their targets by
  stable identity — the instance's `name=` literal, the net's variable
  — in the *current* source at apply time, never by spans cached at
  build time. A gesture survives unrelated edits landing between build
  and apply, and a target that no longer resolves refuses cleanly.
- **Validation before write.** Writers re-parse their output before
  committing; a writer that would produce unparseable source is a bug
  and fails the gesture, never the board.
- **Testing.** Every writer has diff-exact tests (assert the whole
  unified diff), idempotence tests, and byte-stability tests for
  untouched regions. Determinism tests extend the existing emitter
  suite: gesture → bytes is a function.

### 4.2 The editability map

Computed per build from the AST of authored files, keyed by instance
path and net name:

```
"root.R_LIMIT":      { editable: true,  file: "board.zen", … }
"root.MATRIX.LED_3": { editable: false, reason: "generated by a `for` loop in matrix.zen:12" }
"LED_A":             { editable: true,  file: "board.zen" }
```

Also resolved here: **pin → kwarg mapping**. Canvas pins belong to
hoisted components (`root.SENSE_DIV.R1.R`, per 0008's module collapse),
but the editable unit is the nearest literal call — the generic
wrapper's io names (`P1`, `A`, `K`) translate the pin back to a kwarg
on that call. Pins whose nearest literal call is in a *different*
authored file than the gesture's other end are still editable (writers
can touch two files); pins that only resolve inside stdlib or inside a
generated region are not.

The map ships in `BuildView` (bump `BUILD_PAYLOAD_VERSION` +
`types.ts`), so the canvas greys affordances *before* a gesture starts,
and is surfaced to the agent via `get_instance` / `get_board_state`.

### 4.3 The write gate

All writers — canvas commands and MCP tools alike — pass through a
per-window serialized gate in the Rust backend (lives beside the
builder task in `state::Registry`):

- Writes are queued and applied one at a time.
- Every request carries the `source_hash` it was computed against; a
  mismatch rejects with `stale` and the frontend re-offers after the
  rebuild (see §8).
- The gate records before/after byte snapshots per touched file — the
  undo stack's raw material (§7.F).

There is deliberately no watcher echo-suppression: the rebuild after a
gesture IS the confirmation, exactly as with drag-to-move today.

### 4.4 The gesture overlay

The viewer stays a renderer. Direct manipulation renders in an overlay
`<div>`/SVG above `SchematicViewer`, sharing its camera by mirroring
the fit + pan/zoom transforms — the same technique `CircuitCanvas.tsx`
already uses to glue the dot grid to the board. The overlay owns:

- **Pin hit-targets** from `schematic_port` geometry in circuit_json
  (positions are already in the payload; ids resolve via `id_map`).
- **Ghost symbol** during placement (symbol outline from circuit_json
  of the palette item, or a simple bbox for new parts).
- **Wire preview** during pin-drag (manhattan preview; §7.C explains
  why the final routing may differ).
- **Marquee** rectangle for rubber-band select.
- **Inline text editing** for net labels and values (a positioned
  input, not viewer chrome).

Vendored-patch surface grows only if hit-testing needs data the DOM
doesn't already carry.

## 5. What users can do (feature areas)

### A. Add components (palette)

A left-sidebar palette with two tiers:

- **Local**: stdlib generics (R, C, L, LED, diode, …) and this
  project's `components/` — instant, offline (`list_library` data).
- **Parts search**: the live LCSC tier (`search_parts` data) with
  stock, price, and Basic/Extended badges, Basic-first per policy.
  Choosing a part runs the existing add_component pipeline (fetch →
  convert → vendor → card) with a progress state, then arms placement.

**Placement**: click a palette item → ghost symbol follows the cursor
(`R` rotates in 90° steps) → click to drop. Esc cancels; nothing is
written until the drop. The drop is one `add_instance` verb:

- an instantiation statement in the board entry file, inserted after
  the last existing instantiation (before `Board(...)`), with a
  generated unique name (`R1`, `C3`, … from the symbol prefix);
- an authored position for the new instance in the same write — and,
  on a derived-layout board, a save-all snapshot of every current
  position first, so the arrangement the user sees becomes authored
  (the all-or-nothing rule, same as first drag today);
- for generics, an inline value prompt at the drop point (type `10k`,
  Enter; Esc accepts the default).

The instance name appears pre-selected for typing immediately after
drop (the Figma rename affordance) — committing it runs
`rename_instance` before anything else references it.

### B. Create components (wizard)

A dialog shell over the existing verbs, for parts that don't exist in
the palette:

- **From LCSC part number** — paste `C…` → `get_part` preview (incl.
  the EDA-quality probe) → install via the existing pipeline.
- **From files** — the user-supplied `.kicad_sym` (+ optional
  `.kicad_mod`) escape hatch → `add_component` with `symbol_library`.
- Both paths end armed for placement (feature A), and both produce the
  standard unit: wrapper + card (`[provenance] verified = false`) +
  vendored assets.

No new backend surface: this is UI over `add_component` /
`install_component` exactly as the agent uses them today.

### C. Link cables (wire pin-to-pin)

Drag from one pin to another. The gesture is the endorsed compound
edit, the `connect_pins` verb:

```
draw wire R1.P2 → C1.P1
  ↓ edit board.zen:
   +  SIG = Net("SIG")
   ~  Resistor(name="R1", ..., P2=SIG)
   ~  Capacitor(name="C1", ..., P1=SIG)
  ↓ watcher rebuild → canvas
```

Cases, by the endpoints' current nets:

- **Neither connected** → create a net (auto-named from the driving
  pin, e.g. `R1_P2`, sanitized and unique — §12.1) and set both
  kwargs. The new net's label appears pre-selected for renaming.
- **One connected** → set the unconnected pin's kwarg to the existing
  net's variable. No new definition.
- **Both connected, same net** → no-op (already connected).
- **Both connected, different nets** → a **merge**: confirm dialog
  ("connect will merge NET_B into NET_A — N pins move"), then rewrite
  every authored reference of B to A and delete B's definition.
  Refused if any reference to B lives in a generated region.
- **Endpoint on a wire segment** (junction) → resolves to that trace's
  net via `id_map`; behaves as "one connected".
- **Endpoint on a module port** (e.g. `SENSE_DIV.VIN`) → supported;
  the kwarg lives on the module call.
- **Endpoint inside a submodule's internals** whose call isn't in an
  authored file, or whose instance is generated → refuse with the
  reason and the two escape hatches (wire the module's port instead /
  ask the agent).

**Disconnect**: select a pin's wire (or the pin) → Delete removes that
pin's kwarg when the io is optional; when the module requires the pin,
refuse with the reason. A net definition left with zero references is
pruned in the same write (a reviewer would want the dead line gone).

**What persists is connectivity, not geometry.** The drawn wire writes
net membership; the deterministic router (route.rs) draws the result.
The preview is manhattan and approximately right, but the final
rendering may differ — including falling back to net labels when the
net exceeds the local-signal thresholds (>4 ports, wide span). This is
the same honesty contract as 0008: a labeled net is correct; the
router, not the gesture, owns wire paths. Authored waypoints are a
possible later layer (`# pcb:sch` wire keys), out of scope for v1.

### D. Nets: create, rename, rails

- **Create by wiring** (feature C) is the main path.
- **Create by labeling**: a "net label" palette tool → click a pin →
  inline name input → connects that pin to the named net, defining it
  (`NAME = Net("NAME")`) if new. This is how far-flung nets are built
  without dragging wires across the board.
- **Rails**: GND / power palette items place the same way but define
  `Ground("GND")` / `Power("VCC_3V3")`; typed rails win over name
  inference (0008) and get rail treatment in layout.
- **Rename**: double-click any net label → inline edit → the
  `rename_net` verb renames the variable, the string literal inside
  `Net("…")`, and every authored reference (kwargs, across authored
  files). Validation: legal identifier after sanitization, no
  collision with an existing name in scope. Refused if any reference
  sits in a generated region. Renaming an `io(...)`-declared port net
  renames the io in the defining module *and* the kwarg at every
  literal call site; refused if any call site is generated.
- **Delete**: deleting a net's last wire prunes it (feature C);
  deleting a net outright from the label (Delete on a selected label)
  disconnects all its literal pins and removes the definition, with a
  confirm listing the affected pins.

### E. Direct manipulation: select, move, edit, delete

- **Selection** exists (click, shift-click); add **marquee**
  rubber-band select in the overlay, and **multi-move** (drag any
  selected member moves the set — the save-all writer already makes
  this a single write).
- **Rotate**: `R` on a selection rotates 90°; persists via the
  positions path (`rotation` already round-trips). Mirror is out of
  scope for v1 (the field round-trips but has no UI).
- **Edit value/params**: double-click a component's value text →
  inline edit → `set_attribute` replaces just the kwarg's value span
  (`value="1kohm"` → `value="10kohm"`). Other params (package, color)
  edit through a small popover on the selection — same verb, no
  persistent inspector panel.
- **Rename instance**: double-click the refdes/name → `rename_instance`
  rewrites the `name=` literal and migrates the instance's `# pcb:sch`
  position keys in the same write (never orphan a position).
- **Delete component**: Delete on a selection removes the instance
  statement(s), prunes now-unreferenced literal net definitions, and
  rewrites the position block without the deleted keys (the save-all
  writer prunes naturally). Confirm when the delete cascades (nets
  merging away, >3 instances).
- Generated instances render normally but grey out edit affordances
  (move is still allowed — positions are per-component annotations and
  already work for generated instances; structural edits are not).

### F. Undo / redo

- Per window, per gesture: the write gate records before/after bytes
  of every touched file. Undo restores the before-bytes, guarded by a
  hash of the after-bytes; redo is symmetric. One gesture = one undo
  step, even when it touched multiple files (add-component's scaffold
  unit reverts as one).
- If a file moved on since the entry (the agent or the user's editor
  wrote it), that entry — and everything under it for that file —
  invalidates with a toast, rather than clobbering the newer work.
  Cross-checking is per file, so undoing a move doesn't die because an
  unrelated file changed.
- Agent edits are never on the human undo stack. The durable
  trajectory for both users is git; undo is a session convenience, not
  history.
- Scope: structural gestures and moves. Not camera, not selection.

## 6. Agent parity (MCP surface)

Each verb lands as an MCP tool the same release its gesture ships;
both call the same `zen_build::edit` function through the same write
gate. Proposed additions (annotations per the 0003 rules; all
`destructive: false` except where noted, all guarded by `source_hash`):

| tool | maps to | notes |
| --- | --- | --- |
| `add_instance` | A | instantiate an installed/stdlib module: name, attrs, optional pin bindings + position (`find_empty_space` composes) |
| `connect_pins` | C | the compound verb; optional `net` name to use/create |
| `disconnect_pin` | C | remove one pin's binding |
| `create_net` | D | explicit definition; `kind: signal\|power\|ground` |
| `rename_net` | D | destructive-ish: touches many spans; annotated idempotent |
| `set_attribute` | E | kwarg value replacement |
| `rename_instance` | E | includes position-key migration |
| `remove_instance` | E | destructive: true; returns the removed statement text |

(Existing tools already cover the rest of the loop: `search_parts` /
`get_part` / `add_component` for sourcing, `set_positions` /
`find_empty_space` / `check_layout` for layout, `get_selection` for
"do it to what I'm pointing at".)

`board-manual.md` (the single source of agent working rules) gains a
section: **prefer the edit verbs over raw text edits** for
connectivity, nets, renames, and instance add/remove — verbs are
hash-guarded, formatting-safe, and keep the human's undo/conflict
model coherent; text-edit only what the verbs can't express (logic,
loops, module authoring). Tool references in tools.rs stay in sync as
ever.

The selection contract completes the loop: the human's selection is
already the agent's context (`get_selection`), and both sides speak
dotted instance paths — a gesture the canvas refuses hands the agent
everything it needs ("connect root.MCU.PA3 to SENSE_DIV.VOUT — the
canvas refused because MCU pins are generated").

## 7. The hard problems, confronted

1. **Editing generative source** → the editability map (§4.2): static
   AST classification, grey-out before the gesture, refusal with a
   reason after, agent as the escape hatch. No AST round-tripping of
   arbitrary code, no "append-only region" markers polluting source.
   The classifier is conservative: anything not provably a literal
   top-level call/assignment is generated.
2. **Net identity & naming** → nets are variables; the writers treat
   the variable name and the `Net("…")` string as one identity and
   keep them in sync. Create = insert definition; rename = rename
   variable + string + all authored references; merge = rewrite refs +
   delete definition (confirmed); orphan definitions are pruned. All
   refused when any reference is generated.
3. **Human/agent concurrency** → the write gate (§4.3) serializes all
   structured writes and generalizes the `source_hash` token to every
   verb. Agent freeform Edit/Write can't be gated — mitigated by the
   board-manual rule steering the agent onto the verbs, and by the
   hash guard catching the human's stale gesture the moment the agent
   writes anything. See §8 for the conflict UX.
4. **Which file does a gesture touch** → per-gesture mapping:
   placement/wiring/nets edit the file owning the target's literal
   call (usually the board entry); add/create component writes the
   scaffold unit under `components/`; moves/rotates write `# pcb:sch`
   blocks; nothing edits stdlib, vendored assets, or generated
   regions. Cross-file gestures (rename_net across authored files,
   connect_pins spanning two files) write each file once, entry file
   last.
5. **Undo/redo over text-diff persistence** → gate snapshots (§5.F):
   byte-exact, hash-guarded, invalidate-don't-clobber. No shadow git
   commits.
6. **Formatting preservation** → span surgery + diff-exact tests
   (§4.1). The review test from docs/product.md is a literal test
   suite: every writer asserts its unified diff.

## 8. Conflict & failure UX

- **Stale gesture** (hash mismatch): toast "the board changed while
  you were editing". After the rebuild, the gesture re-validates
  against the new build — if its targets still resolve (same pins,
  same nets), one-click "apply anyway"; if not, it drops with an
  explanation. Never auto-apply across a semantic change.
- **Refused gesture** (generated region, required pin, name
  collision): inline callout at the gesture site with the writer's
  reason and, where apt, a one-click "ask the agent to do this" that
  pre-fills the chat with the verb, targets, and refusal reason.
- **Red board** (build failing): editing stays available — the canvas
  is often the fix (delete the offending part, reconnect the wrong
  net). Gestures are computed against the last good build's geometry
  (the canvas still renders it), and name-anchored application (§4.1)
  is the guard: targets that no longer resolve in the current source
  refuse per-target, and a file that no longer *parses* refuses
  structured edits entirely ("board.zen doesn't parse — fix it in the
  editor or chat"). The `source_hash` token can't gate here (current
  bytes are past the last good build by definition), so apply-time
  resolution carries the whole safety burden on a red board. The
  "build failing" chrome stays up; the rebuild after the fixing
  gesture clears it.
- **Mid-gesture rebuild** (agent wrote while the user drags): the
  overlay finishes the gesture against the build it started on; the
  hash guard decides at commit. The canvas never swaps geometry under
  an active drag — the rebuild applies when the gesture ends.

## 9. Phasing

Safest-first: each phase ships writers whose blast radius is closest
to existing precedent, and every phase ships its MCP twin + manual
update in the same release.

- **Phase 0 — foundation.** `zen_build::edit` skeleton, editability
  map in `BuildView` (+ payload bump), write gate, overlay scaffolding
  (camera mirror, pin hit-targets, hover affordances). Exit: pins
  highlight on hover; `get_instance` reports editability; no writers
  yet.
- **Phase 1 — add & create components.** Palette (both tiers), wizard,
  ghost placement, `add_instance` + `rename_instance`, inline value
  prompt. Extends scaffold.rs precedent; the first program-text writer
  is append-shaped (lowest risk). Exit: blank project → placed,
  named, valued parts without opening an editor.
- **Phase 2 — nets.** `create_net`, `rename_net`, label placement,
  rails, pruning. Variable-level edits in flat authored source. Exit:
  double-click-rename on the demo board produces the exact expected
  diff.
- **Phase 3 — wiring.** `connect_pins` / `disconnect_pin`, junctions,
  merge confirm — the compound edit. Exit: the endorsed example is a
  literal integration test (gesture → asserted diff → rebuild →
  routed wire or honest label).
- **Phase 4 — manipulation completeness.** Marquee, multi-move,
  rotate, delete with cascades, `set_attribute` inspector, undo/redo
  surfaced (gate has recorded since Phase 0).
- **Phase 5 — collaboration hardening.** Conflict UX polish, the
  board-manual steering rules, refusal→chat handoff, and a scripted
  two-driver test: agent adds a part, human wires it, agent renames
  the net, human repositions — one clean git log at the end.

## 10. Success criteria

- The demo board can be built from an empty project entirely on the
  canvas — no editor, no chat — and the resulting `board.zen` is
  within normal human authorship (a reviewer can't tell).
- Every gesture's diff is minimal and readable: the diff-exact test
  suite is green, and no gesture ever reformats untouched lines.
- Determinism holds: gesture → bytes and bytes → schematic both stay
  pure functions (existing byte-determinism tests extended over the
  writers).
- The two-driver script (Phase 5) passes: no lost writes, no stale
  misapplies, a git history that reads as collaboration.
- Refusals are complete: fuzzing gestures against generated-instance
  fixtures produces zero silent misedits — every outcome is applied
  correctly or refused with a reason.

## 11. Out of scope (v1)

- Authored wire geometry / waypoints (router owns paths).
- Bus/vector nets, differential-pair awareness.
- Creating or restructuring submodules from the canvas (grouping a
  selection into a module is a natural v2).
- Editing generated instances (the agent is the path).
- Mirror UI, net-label position dragging (`sym:` keys), text/graphic
  annotations.
- PCB layout editing (schematic only).
- Multi-user (beyond the one human + one agent per window we have).

## 12. Resolved questions (2026-08-09)

Decided with the product owner; the sections above already reflect
these.

1. **Auto net naming** — pin-derived (`R1_P2` from the driving pin,
   sanitized, unique), label pre-selected for immediate rename. Not
   counters, not a mandatory prompt.
2. **Prune policy** — auto-prune: the write that orphans a net
   definition removes it. No dead variables in diffs.
3. **Instance naming** — refdes-style (`R1`, `C3`, `U2` from the
   symbol prefix, unique in file), name pre-selected after drop for
   optional rename. No mandatory naming prompt.
4. **Net merges** — always confirm, regardless of size. Merges rewrite
   many spans and delete a definition; never silent.
5. **Value editing** — inline-only: double-click edits the value in
   place; other params via a selection popover. No persistent
   inspector panel.
6. **Red board** — editing stays available; the canvas must be able to
   fix a failing build (§8). Name-anchored apply-time resolution is
   the guard, not a green-build requirement.
